系统设计

一面丢分最多

拍一张商品照片问“这是啥”，系统怎么设计

为什么会问：一面原题。面试官提示“不光是一个多模态模型能解决的”，当时把 OCR 的作用说反了，而且卡了很久。

  1. 意图理解与路由：用户想识别、比价、问用法，还是鉴别真假？图片是商品、文字、题目还是动植物？
  2. 视觉预处理：用 grounding 或检测把主体框出来并裁剪，去掉背景（否则以图搜图的向量会被背景污染）。用 OCR 读出品牌和型号，这是最强的线索。
  3. 工具循环：以图搜图（SigLIP / CLIP 双塔向量 + ANN 检索）得到候选；OCR 文本加候选标题做文本搜索；置信度低就改写 query 重搜，或者追问用户。
  4. 重排验证：VLM 把候选和原图逐一比对 logo、外观、文字，防止“同款不同型号”。
  5. 带证据生成：每个结论都要对应某个工具的返回，不确定时给“可能是 A 或 B”。

训练：先用 SFT 冷启动，再做 Agentic RL，奖励 = 答对 − 调用成本。评测：准确率、调用次数、延迟、幻觉率。

场景题通用答法：先定指标和约束（延迟、准确率、成本），再讲两阶段方案：先用现成工具搭 Agent 上线、积累数据，再训专用模型；最后讲 bad case 怎么回流。

拍照解题的系统设计

  1. 版面分析、题目切分，OCR 加公式识别（转 LaTeX）。几何图、函数图要保留视觉输入，不能只转文字。
  2. 先搜题库（以图搜题或文本检索），命中就基于标准解析改写讲解，又快又准。
  3. 没命中就让 VLM 逐步推理，数值计算交给计算器或代码执行，最后把答案代回验算。
  4. 输出分步解析。评测看最终答案正确率加步骤正确率。
  5. 难点：手写和拍照模糊、几何的视觉推理、答案对但过程错。

为什么不直接让 VLM 回答，一定要搜索

  • 商品和实体是长尾知识，而且更新快，参数里的知识覆盖不了新品和小众品牌，模型会编型号。
  • 搜索结果可以溯源、可以引用，对应 JD 里的“检索引用”。
  • 代价是延迟和成本，所以按需搜索：简单、明确的问题一轮就答，复杂的才进多轮循环。

VLM 结构

一面只答到“CLIP + 投影层”

通用结构：视觉编码器 + 连接器 + LLM

  • 视觉编码器：ViT（CLIP 或 SigLIP 预训练），把图切成 patch，得到视觉 token。
  • 连接器：线性层或 MLP（LLaVA，不压缩 token 数）；Q-Former / Perceiver Resampler（BLIP-2、Flamingo，用可学习 query 压成固定数量）；cross-attention 注入（Flamingo）；token 合并（Qwen2-VL 把相邻 2×2 个 token 合成 1 个，InternVL 的 pixel shuffle）。
  • LLM：视觉 token 和文本 token 拼接后自回归。
  • 训练阶段：先只训连接器做对齐，再图文预训练，再指令 SFT，最后偏好对齐或 RL。

Qwen-VL 系列演进

版本要点
Qwen-VLViT + 单层 cross-attention 适配器，把图压成 256 个 token，固定 448 分辨率；grounding 用 <box> 加归一化到 [0,1000) 的坐标文本
Qwen2-VL原生动态分辨率（ViT 用 2D-RoPE 支持任意分辨率，token 数随图大小变化，再用 MLP 做 2×2 合并）；M-RoPE 把位置编码拆成时间、高、宽三个分量，文本的三个分量取同一个值、等价于 1D RoPE；图像和视频统一处理
Qwen2.5-VLViT 大部分层改成窗口注意力，降低高分辨率开销；视频动态帧率，M-RoPE 的时间维对齐到绝对时间；grounding 改用原图绝对像素坐标；加强文档解析和电脑、手机操作 Agent
Qwen3-VLDeepStack：把 ViT 多层特征注入 LLM 前几层；交错 M-RoPE（时间、高、宽在频率维上交错分配，避免某个轴只拿到低频）；视频用文本时间戳对齐；原生长上下文；有 Dense 和 MoE、Instruct 和 Thinking 版本
Qwen3.5官方定位是原生多模态。记忆中是线性注意力（Gated DeltaNet）与门控注意力混合，加稀疏 MoE。这一条把握不大，面试前必须核对官方博客。你自己的项目就用 Qwen3.5-4B，被问到说不清会很减分
不确定的细节就说“我记得是……具体还要再核实”，不要硬答。这个弱点以前出现过。

现场算图片 token 数（蚂蚁、腾讯现场考过）

patch 为 14、再做 2×2 合并时，token 数约等于 (H/28) × (W/28)。例如 448×448 → 16×16 = 256 个；1024×1024 → 约 37×37 ≈ 1,369 个。实际会先把边长调整到 28 的倍数，并受 min_pixels / max_pixels 约束。

训练和测试分辨率不一致会怎样

  • 固定分辨率的 ViT：位置编码要插值或外推，偏离训练分布就掉点。
  • 动态分辨率模型：分辨率太低，小字和细节丢失，OCR 类任务掉得最多；太高则 token 暴涨，延迟和显存上升，还可能超出训练时见过的长度。
  • 实践中会限制 min_pixels / max_pixels，训练时混合多种分辨率。

CLIP、SigLIP 与 InfoNCE（以图搜图的底座）

  • 双塔结构，batch 内 N 对图文，对 N×N 相似度矩阵做对称交叉熵：L = −log( exp(s_ii/τ) / Σ_j exp(s_ij/τ) )。
  • SigLIP 把 softmax 换成逐对的 sigmoid 二分类，不需要全 batch 归一化，对大 batch 更友好。
  • 商品检索：同款不同角度当正样本，同品牌的相似款当难负样本。温度 τ 控制分布的尖锐程度。

grounding

把坐标当文本 token 预测；Qwen-VL 用 [0,1000) 归一化坐标，Qwen2.5-VL 用绝对像素坐标（Qwen3-VL 用哪种，面试前核对）。在 Agent 里用来先框出主体再裁剪，或者做放大工具。

数据与评测

千问多模态岗爱问

评测基准

  • 通用：VQAv2、MMBench、MMMU。OCR 与文档：TextVQA、DocVQA、ChartQA、InfoVQA。
  • 必须检索的知识型：OK-VQA、A-OKVQA、InfoSeek、Encyclopedic-VQA。多模态搜索：MMSearch。
  • 数学与拍题：MathVista、MathVerse、MathVision。
  • 评测方式：短答案用规则匹配；开放答案用 LLM 加评分细则判；搜索类再看调用次数、延迟、引用是否正确。

多模态训练数据怎么造（面经原题：一条样本长什么样、图文一致性怎么过滤）

  • 来源：线上真实 query 回流（脱敏 + 标注）、强模型合成 caption 和 QA、渲染合成的图表和文档、题库图片配解析。
  • 流程：采集 → 规则过滤 → 模型打分（CLIP 相似度、VLM 判官）→ 去重（感知哈希或向量聚类）→ 难度分层 → 配比消融。
  • Agent 轨迹：用强模型在真实工具环境里跑，只保留答案正确、调用合理的轨迹（拒绝采样）。
  • 面经追问：有了 caption 为什么还要造 VQA 和推理数据？因为 caption 只教“描述”，问答和推理数据教的是“根据问题定位证据、多步推理”，对应下游任务的格式和能力。
  • 有没有必要造极短回答的数据（比如只答物种名）？有：拍照识物的核心是给出准确实体名，短答案让 loss 集中在关键 token 上，也训练模型不啰嗦。

涨了 1 个点，是真提升还是噪声

多个随机种子、每个任务多次采样、配对 bootstrap 置信区间，报 pass@1 和 pass^k。还要用纯文本基线（把图遮掉）排除“不看图也能答对”的题。这是你的强项，可以主动讲自己项目里怎么做的。

Agent 与工具调用

  • 常用工具：以图搜图、文本网页搜索、OCR、裁剪和放大、代码执行、计算器、商品库或题库查询。
  • 代表工作（细节面试前核对）：MMSearch-R1（用 RL 学何时搜图、何时搜文本，惩罚不必要的搜索）；DeepEyes 等“边看边想”的工作（把放大当工具）；通义 WebWatcher（视觉语言深度研究 Agent）。
  • 关键设计：工具返回统一成观察；上下文管理（图片 token 很占地方，可以摘要或丢掉旧图）；SFT 时工具返回部分不计 loss。
  • 为什么用 Agent 而不是固定流程：决策空间是开放的，需要根据观察反馈决定下一步；固定流程覆盖不了长尾（你的项目里：规则流水线长尾 36%，LLM 84.5%）。
  • 场景题：线上 Agent 老在调工具不回答，怎么定位：看奖励里工具奖励是否过高、停止条件、工具返回是否太长挤占上下文、SFT 数据里调工具的轨迹占比是否偏高；按“规划 / 工具选择 / 参数 / 执行 / 总结”分层埋点归因。
  • 视觉工具坐标幻觉怎么兜底：坐标归一化、越界裁剪、校验后重试。

RAG 与幻觉

从概率角度解释 RAG 为什么能降幻觉（面经原题）

没有检索时，生成靠参数知识 p(y|x)，长尾事实在训练分布里概率质量低，模型会按语言先验补出流畅但错误的答案。检索后变成 p(y|x, d)，相关文档大幅抬高正确答案的条件概率，熵下降，模型从“回忆”变成“抄写和归纳”。前提是检索要准，所以需要重排、多路召回、引用约束，以及“证据不足就拒答”。

多模态 RAG 两条路线

  • 图片直接做向量，以图搜图或跨模态检索：保留视觉细节，但对背景和角度敏感。
  • 先转文本（OCR 或 caption）再按文本检索：能复用成熟的文本搜索，但转写会丢信息。
  • 工业上两路并行再融合（如 RRF），用 VLM 精排；生成时每个论断标注来源编号，引用正确率可以作为奖励或偏好信号。

多模态幻觉

  • 成因：语言先验压过视觉证据；长生成中对视觉 token 的注意力衰减；分辨率不足；训练 caption 本身有幻觉。
  • 评测：POPE（物体是否存在的问答）、CHAIR（caption 物体幻觉率）；Agent 场景看“没有工具证据支撑的论断占比”。
  • 缓解：解码侧 VCD、OPERA；训练侧幻觉偏好对（RLHF-V、RLAIF-V）、多模态 DPO 加“同一回答配破坏过的图”负例；系统侧检索 + 引用、放大复看、低置信时给多个候选或追问。
  • 怎么验证模型不看图也能答：把图遮掉，看纯文本能答对多少，再看视觉 token 的注意力占比。

后训练

一面追问到第二层

DPO 与 SimPO

  • DPO：L = −log σ(β[log π(y_w)/π_ref(y_w) − log π(y_l)/π_ref(y_l)])。没有显式 KL，约束隐含在 β·log(π/π_ref) 里，β 就是 KL 系数。π 是整条回复的序列 log 概率，不是最后一层 logits。
  • SimPO：L = −log σ(β/|y_w|·log π(y_w) − β/|y_l|·log π(y_l) − γ)。没有参考模型、没有 KL。β 是奖励缩放，γ 是目标间隔（要求好回答至少高出 γ），不是防偏离。
  • SimPO 的核心动机：让训练奖励和生成时的平均似然一致；去掉参考模型只是附带好处。长度归一化是为了消除长度偏差，不是约束回复长度（这句错过两次）。
  • DPO 的缺陷：离线、分布偏移；chosen 的概率也会被一起压低；对长度偏好过拟合；只有相对信号。
  • KL 放在哪：PPO-RLHF 放在奖励里（每个 token 扣 β·log(π/π_ref)）；GRPO 直接放在 loss 里，用 k3 估计。
不要再说“DPO 显存爆了所以用 SimPO”：LoRA 下参考模型就是关掉 adapter 的基座，不额外占显存，只是多一次前向。

GRPO

  • 优势 A_i = (r_i − mean) / std（是标准差）；目标里是重要性比率 × 优势，加 clip，减去 β·KL（k3），按 1/G 和 1/|o| 归一化。
  • 方差小不是问题，除以标准差会放大；方差为 0 才是问题：全对或全错时优势为 0，没有梯度，还稀释 batch。除以 std 还会带来难度偏差，所以 Dr.GRPO 去掉了它。
  • 训推串行时还需要重要性采样吗：需要。一批数据分多个 mini-batch 更新，从第二步起就是 off-policy；而且推理用 vLLM、训练用 FSDP，同一份权重算出的 log 概率也对不上，要用 TIS / MIS 修正（得分点）。
  • DAPO 四招：动态采样（过滤全对全错的组）、clip-higher（防熵塌缩）、token 级 loss 聚合、超长样本软惩罚。
  • 序列级优势的问题：没有信用分配；长度偏差。DAPO 在所有 token 上统一平均，Dr.GRPO 去掉 1/|o|，GSPO 把重要性比率改到序列级，MoE 上更稳。
  • 熵塌缩：熵快速下降、pass@k 不涨。原因是高概率且优势为正的 token 被不断加强、clip 让低概率 token 难以被调高（Cui 等人：log 概率与优势的协方差为正）。缓解：clip-higher、动态采样、提高温度、谨慎加熵正则、Clip-Cov / KL-Cov。
  • PPO 和 GRPO：PPO 有 critic，用 GAE 算 token 级优势；GRPO 用组内归一化代替 critic，省显存，但只有序列级信号。

OPD、GKD、forward 与 reverse KL（一面连续三个“不了解”）

  • OPD：学生自己生成，老师在学生的序列上逐 token 打分，最小化 reverse KL(π_学生‖π_老师)。比 SFT 蒸馏少了曝光偏差，比 RL 信号稠密。
  • 按老师给的信息量：完整词表概率（最全、最贵）/ top-k 概率再归一化 / 只给采样 token 的 log 概率（最便宜，可直接当奖励，方差最大）。
  • 按数据来源：在线、离线、混合（GKD 用比例 λ 混合）。变体：OPSD（同一模型看到额外信息时当老师）、多老师 OPD。
  • GKD 式与策略梯度式：GKD 式直接对散度求梯度（广义 JSD，在 forward 与 reverse KL 之间插值）；策略梯度式把 log π_老师 − log π_学生 当作 token 级奖励，可以和任务奖励相加（Thinking Machines 的做法）。
  • forward KL：覆盖均值，学生要覆盖老师所有有概率的地方，期望在老师分布下取，SFT 交叉熵就是它。reverse KL：锁定峰值，学生挑一个峰拟合，期望在学生分布下取，天然在线。
  • 你项目里没做 OPD 的理由（一面说过，是好理由）：GLM 的 API 拿不到学生序列上的逐 token 概率；GLM 和 Qwen 词表不同，需要跨分词器对齐。

三个研究课题

主动带出

课题 1：SFT 训到什么时候就够了

  • AceReason-Nemotron 1.1（NVIDIA）：SFT 越强，RL 后最终越好；RL 会缩小差距但不改变排名，前提是采样温度把熵维持在约 0.3。
  • SFT Overtraining Predicts Rank Inversion（ICML 2026）：SFT 训过头会让 RL 后排名反转，原因是熵已经塌了；RL 前测一次平均 token 熵比看 pass@k 更能预测 RL 效果。
  • WiSE-FT / AESL：SFT 中 pass@1 一直涨，pass@k 很快下降；多样性开始下降时就该停。
  • Yue 等（NeurIPS 2025 oral）：RL 主要提升 pass@1，k 很大时基座的 pass@k 会追上；pass@k 与 pass@1 的差距就是 RL 能挖的空间。
  • ARPO（ICLR 2026）：每次工具返回后，接下来几个 token 的熵会明显升高。
为什么带工具后熵不好用：整体 token 熵被两类 token 扭曲，工具调用的 JSON 格式 token 熵天然很低（把平均值拉低），工具返回后的 token 熵又很高（ARPO 的发现）。所以要换成只在决策点上算的指标：工具调用合法率是否饱和；pass@k 与 pass@1 的差距；组内有区分度的样本占比；关键决策点（搜不搜、调哪个工具、填什么参数）的熵；对每个决策点采样多个候选，看有多少比例会出现不同动作（“有效负例率”）。可以设计实验：不同 SFT checkpoint 接同样预算的后续训练，看哪个指标最能预测最终收益。

你正在跑的重构项目里就做了这个实验（不同 SFT checkpoint 上算这些指标，再接同样预算的 Agentic-DPO）。结果出来之前，只讲设计，不讲结论。

课题 2：OPD 里老师的问题

  • 学生生成的前缀可能是老师自己永远不会走到的状态，老师在这些状态上的打分不可靠。
  • 能力差距太大，学生学不动，可以用中等大小的老师过渡。
  • 词表不一致需要对齐。
  • reverse KL 会降低多样性，和后续 RL 的探索相冲突。
  • 你的项目：在学生自己走到的状态上让老师接管，并比较老师在“专家状态”和“学生状态”上的成功率；老师的标注必须通过环境校验才采用。

课题 3：Agent 训练中的信用分配

  • 先讲自己的：环境校验器能定位第一次出错的步骤，只惩罚出错步；偏好对在偏离点构造，天然是步级信用。
  • 业界：GiGPO（同组轨迹中找环境状态相同的步骤，再分组算步级优势，A = A_轨迹 + ω·A_步）；过程奖励模型；树搜索采样（从中间分叉，用蒙特卡洛估每步价值）；按轮给奖励；PPO + GAE。

手撕与智力题

  • 高频手撕：MHA / self-attention（带 mask，约 7 次）、RoPE、最长公共子序列、最长回文、岛屿数量、无重复字符最长子串、判断子序列、PPO / OPD 伪代码、MoE 路由。
